Open work for the ccstatusline fork.

## 1. ccstatusline

- [x] **Fix eslint-plugin-import crash on ESLint 10.** (p2) [chore] `import/order` threw `sourceCode.getTokenOrCommentAfter is not a function` whenever it reported a violation, which hid real lint errors. Resolved by the move to eslint-plugin-import-x: a deliberate misordered import now reports `import-x/order` errors cleanly (checked 2026-11-03).
- [x] **Stabilize flaky TUI tests.** (p2) [test] The lost keypresses were a real bug: List took its own reported position back through initialSelection after a newer keypress and jumped back. Fixed in List with a regression test, and the ItemsEditor and ColorMenu tests now wait for each key's visible effect instead of a fixed flushInk() delay. The test helper also waits 10 event-loop turns instead of 2 after each frame, because the dev-reload tests pressed ctrl+r before the position reached App. The full suite ran clean 3 of 3 times under load (2026-11-04). TerminalWidthMenu's test went away with the upstream merge.
- [x] **Fix fetchUsageData test timeout.** (p2) [test] "preserves root errors within a process" makes 10 probe runs, each spawning a subprocess, and needs about 5.4s alone, so it hit the 5s default; "keeps alternating failure deadlines" hit it too under load. The whole file now has a 30s limit.
- [ ] **Explore width options to stop the line jumping around.** (p2) [feature] Per line or per widget: reserve a placeholder width even when a widget is empty; cap a widget's width and truncate with an ellipsis at the start or the end; let widgets right-align, either by giving a line min/max widths or by measuring every line and padding them all to the widest one. Check what powerline autoAlign, maxWidth and flex separators already cover before adding new settings. Upstream removed the Terminal Width options in #765 (lines now always use the full width minus 5), so flexMode and compactThreshold in existing settings are ignored; a replacement for full-until-compact belongs here if it is missed.
- [ ] **Threshold colors for numeric widgets.** (p2) [feature] Optional per-widget color stops on the widget's number, e.g. cache hit rate >80% green, 20-80% yellow, <20% red. Offer hard steps and a smooth blend between the stop colors, built at the active color level (ansi256 or truecolor; plain steps at ansi16). Decide the config shape (a list of {value, color} stops in metadata?), which widgets opt in (anything with supportsNumberFormat is a start), whether higher is better or worse per widget (context % wants the reverse of cache hit), and how it interacts with global FG overrides and themes.
- [x] **Quit with q on the main menu.** (p2) [feature] Exits straight away with nothing unsaved; with unsaved changes it prompts to save, discard or keep editing.
- [ ] **Session Lines Changed widget.** (p2) [feature] Show cost.total_lines_added / total_lines_removed from the status JSON (already parsed in StatusJSON.ts, no widget uses them). Unlike Git Insertions/Deletions, this counts what Claude changed this session, not the working-tree diff.
- [x] **Usage Pace widget.** (p2) [feature] Covered by upstream's Block Forecast, Block Limit Timer, Weekly Limit Timer and Weekly Fable Limit Timer, which arrived in the 2026-11-03 merge. Original idea: project when the 5h (and weekly) limit runs out at the current rate from usage % and time elapsed in the window, e.g. "limit in ~1h20m" or "on pace". The usage API only reports percentages, so it projects time, not tokens.
- [ ] **API Time Share widget.** (p3) [feature] Share of session time spent waiting on the model: cost.total_api_duration_ms / total_duration_ms. SessionCostRate reads both but nothing shows the ratio.
- [ ] **Turns Until Compaction widget.** (p2) [feature] Estimate how many turns are left before auto-compact from the average context growth of the last few turns (transcript) and the room left under the usable window, e.g. "~6 turns to compact". Earlier warning than a percentage.
- [ ] **Last Turn Cost widget.** (p3) [feature] Cost of the most recent turn next to the session average, so expensive turns (a big cache write after a pause) stand out. Needs per-turn usage from the transcript priced per model.
- [ ] **Tool Usage Summary widget.** (p3) [feature] Counts of tool calls this session from the transcript, e.g. "Edit 12 · Bash 5 · Read 30", with a configurable top-N.
- [ ] **Active Subagents widget.** (p3) [feature] Number of subagents running right now. First check the transcript records enough (sidechain entries, start/finish) to detect this reliably; drop the item if it doesn't.
- [x] **Update README and USAGE for 2.3.0-2.8.2.** (p2) [docs] README has a section on the fork in Recent Updates, and USAGE covers separator presets, tri-state overrides, widget style order, Context Bar labels, vim keys, q, the local install option and Remote Control Status.
- [x] **Merge upstream main.** (p1) [chore] The fork is 66 commits behind upstream/main (merge base at 2.2.32), 38 of them fixes that affect the numbers it shows.
  By commit title: API responses counted twice in speed and token metrics (#622, #725, #735), output tokens counted in context % (#730), stale usage windows (#736), an outdated service status shown as current (#772). Includes the v2.2.33 tag. Expect conflicts around the fork's widget styles and cache widget migrations; re-run the lint and tests afterwards.
- [x] **Fix git-hardening test failing on every local run.** (p1) [test] "keeps Git LFS installed into the repository config" fails in src/utils/__tests__/git-hardening-exec.test.ts, so `bun test` is red locally (3251 pass, 1 fail).
  Under the local Bun 1.3.11, execFileSync without `env` ignores changes to process.env, so the fake git-lfs on PATH and GIT_CONFIG_GLOBAL never reach the child. That also means "keeps running filter drivers from the user's own config" passes without testing anything, and the suite runs against the real ~/.gitconfig. Passing `env: process.env` in both the execGit and plainGit helpers gives 6 of 6 (tried on a scratch copy).
- [x] **Find why loadClaudeSettingsSync fails intermittently in CI.** (p2) [test] At 2.6.0 ThinkingEffort.test.ts stubbed claude-settings with a factory vi.mock, which Bun doesn't limit to one file, and CI's file order varies between runs, so claude-settings.test.ts sometimes ran after it and got the stub. Running the pair on bf0c1c1 fails the same 3 tests every time on Bun 1.3.11 and 1.4.3, and passes on current main. Upstream's 14367e0 fixed it and arrived with the 2026-11-03 merge; no project module has a factory mock now.
